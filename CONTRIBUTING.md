# Contributing to AuraContent 🎬

Thanks for your interest! Bug fixes, new channels, new providers (LLM, TTS, visuals, platforms) and doc improvements are all welcome.

## ⚡ Quick Start

1. **Fork & clone** your fork:

   ```bash
   git clone https://github.com/<your-username>/auracontent_v2.git
   cd auracontent_v2
   ```

2. **Install** FFmpeg + fonts and the Python dependencies with [uv](https://docs.astral.sh/uv/):

   ```bash
   sudo apt-get install -y $(grep -vE '^\s*(#|$)' packages.txt)
   uv sync --group default --group media --group dev
   ```

3. **Configure your keys**:

   ```bash
   cp .env.example .env    # then fill in at least one LLM key
   uv run python -m auracontent.cli.doctor
   ```

4. **Run the pipeline**:

   ```bash
   uv run python -m auracontent.cli.generate mystery --script-only   # fast: script only
   uv run python -m auracontent.cli.generate mystery                 # full video in output/
   ```

   Only run `auracontent.cli.publish` with test accounts: it posts publicly.

## ✅ Before Opening a PR

Run the same checks as CI:

```bash
uv run ruff check --select F821,F811,F823 --exclude auracontent/channels/kids/legacy .
uv run pytest -q
```

Add or update tests in `tests/` when you change pipeline logic.

## 📝 Commit Messages

Releases and `CHANGELOG.md` are generated by **semantic-release** from commit messages, so follow [Conventional Commits](https://www.conventionalcommits.org/):

| Prefix | Effect |
|---|---|
| `feat(scope): …` | minor release, listed under *Features* |
| `fix(scope): …` | patch release, listed under *Bug Fixes* |
| `perf: …` | patch release, listed under *Performance* |
| `docs: …` | no release, listed under *Documentation* |
| `refactor:`, `test:`, `chore:`, `ci:`, `style:`, `build:` | no release |
| `BREAKING CHANGE:` in the footer (or `feat!:`) | major release |

Examples: `feat(llm): add Mistral provider`, `fix(audio): handle empty TTS response`.

## 🚀 Submitting

1. Branch from `main`: `git checkout -b feat/short-description`
2. Commit, push to your fork and open a **Pull Request** against `main`, describing what changed and how you tested it.
3. CI (`tests.yml`) must pass.

## 🔒 Never Commit

- `.env`, API keys or tokens (put new variable **names** in `.env.example` and in the channel YAML, never values);
- generated media (`output/`, `temp/`, `*.mp4`);
- assets you don't have the rights to redistribute (music, images, fonts).

Happy coding!
